# Web search in chat

Add an explicit Search toggle beside the attachment button. Off by default; only
the current message becomes a search query. Use DuckDuckGo HTML search through the
existing async HTTP client library, with a fixed endpoint, bounded response size,
timeout and validated result links. No extra account, model call or dependency.
This is search excerpts, not full-page browsing. Provider markup/rate limits may
change; errors must be visible rather than silently answering from old knowledge.

Search answers run through the selected local model, with bounded untrusted source
context, current retrieval time and citation instructions. Show a real Sources
list from retrieved results independently of citations generated by the model.
Persist source metadata and actual model input with the response. Successful search
snapshots survive reload/retry; failed searches can be retried. Keep cancellation,
streaming, telemetry and saved chats intact. Stop must also cancel search requests.

Keep PDF chats offline and disable Search there. Web turns stay local even if the
ordinary routing preference permits cloud help; do not silently transmit sources or
chat history to a frontier model. Do not change that saved routing preference.

Verify parser/URL safety and limits, local-only routing, bounded grounding, source
persistence, provider failures, cancellation/retry, frontend selection and sources,
mobile layout, plus a real synthetic search + Gemma answer in an isolated database.
